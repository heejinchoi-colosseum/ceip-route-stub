Shopping Mall Linkage Control — 공용 연결

연결 대상

실제로는 각 서비스가 로그인 후 자기 region·service 를 보유·전달한다. 라우터는 이 값을 서명한 state 에 실어 콜백까지 왕복시킨다. 여기 선택은 호출 서비스 시뮬레이션용.

인증 성공 후 돌려보낼 원 서비스 URL. 상대 경로(/...)는 같은 호스트라 허용, 절대 URL 은 return-allowlist 호스트만 허용. 비우면 결과 화면을 그대로 보인다.

체크 시 콜백이 토큰 교환에 expiring=1 을 붙여 만료형 offline 토큰 (expires_in 3600, refresh_token 90일) 발급. 미체크면 비만료 offline(refresh_token 없음).

체크 시 grant_options[]=per-user 로 online 토큰(약 24h 만료, associated_user 포함) 발급. online 토큰에는 refresh_token 이 없다. 함께 체크하면 위 만료형 Offline 은 무시된다.

동기화 설정 (소비 서비스 소유 · 데모 표시)

sellerId, warehouseId 는 start 가 service 별로 조합해 서명 state 에 싣고, 콜백이 복귀 URL 에 붙인다.

스텁은 인증(shop·region·service)만 처리한다. 동기화 설정 값은 정식 라우트 설계상 소비 서비스가 소유하므로 여기서는 화면 구성용으로만 둔다.
